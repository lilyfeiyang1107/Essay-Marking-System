# 文墨 · H1 华文作文工坊

面向学生和教师的华文作文批改网页。支持记叙文、议论文分别上传，内容30分＋表达30分，文体分析、逐项错别字纠正、一个完整段落优化，以及依据题目的500字以上范文和逐段旁批。

## GitHub 网站发布

源码仓库：`lilyfeiyang1107/Essay-Marking-System`。`docs/` 是已生成的 GitHub Pages 网站文件，不含密钥。GitHub Pages 只运行前端；真实 AI 批改和 DOCX/PDF 解析由独立后端提供。

仓库拥有者在 GitHub 打开 **Settings → Pages → Build and deployment**，选择 **Deploy from a branch → main → /docs → Save**。如仓库为私有且账户方案不支持 Pages，需要先解决 GitHub 的站点托管限制；不要为了上线未经确认就将私有仓库改为公开。

GitHub 部署成功后，默认学生地址应为 `https://lilyfeiyang1107.github.io/Essay-Marking-System/`；以 Pages 设置实际显示的发布地址和部署成功状态为准。在验证成功前，这只是预期地址，不代表网站已上线。

没有后端时，Pages 网站仍可阅读图解课程、离线查看明确标注的示例、在浏览器解析TXT并编辑正文。提交真实作文时会提示服务尚未连接，不会把示例评分当成学生成绩。

### 连接真实批改后端

1. 在 Render 导入此 GitHub 仓库的 Blueprint，仓库根目录的 `render.yaml` 已包含安装、启动、健康检查和 Pages 跨域设置。也可在支持 Python Web 服务的其他平台运行本项目。平台账户、费用及可用方案由部署者确认。
2. 在后端平台安全填写 `ESSAY_AI_KEY`。它是 OpenAI 密钥，不能填写到前端、GitHub Pages 文件或公开变量。`WENMO_ALLOWED_ORIGINS` 应为 `https://lilyfeiyang1107.github.io`，不含仓库路径。CORS 控制浏览器来源，不等于身份验证。
3. 取得实际 HTTPS 后端地址后，生成并提交连接配置，例如（地址须换成你实际部署的服务）：

```bash
.venv/bin/python scripts/build_pages.py --api-base https://YOUR-SERVICE.onrender.com
git add docs
git commit -m "Connect Pages site to the essay grading backend"
git push origin HEAD:main
```

4. 在学生网页验证服务状态，再实际上传作文并批改。没有真实密钥和后端服务时，不能称为完整批改功能已上线。

每次修改前端、示例、图标后运行 `.venv/bin/python scripts/build_pages.py` 并提交更新后的 `docs/`。**已连接后端时必须同时传入原来的 `--api-base` 地址**，否则会生成未连接版本。自定义域名或其他项目路径使用 `--base-path /` 或对应路径。

只想验证纯静态站点时，可将 `docs/` 置于本地静态服务器的 `/Essay-Marking-System/` 目录下检查，必须保留项目子路径，以免遗漏 GitHub Pages 的路径问题。

## 手机 APP（PWA）

现有系统增加了插画首页、手机底部导航、图解写作学习页、情绪曲线图、P.E.E.L 卡片、交互练习和评分条形图。

这是可安装的网页 APP，并非 APK、IPA 或已上架的原生应用。先部署到公网 HTTPS 地址，学生即可用浏览器访问：Android Chrome 可选择“安装应用”；iPhone Safari 使用“分享 → 添加到主屏幕”。页面的“安装APP”按钮会在浏览器支持时打开安装提示，否则展示对应操作说明。浏览器不一定在首次访问时提供安装提示。

彩色应用图标采用蓝绿底色、书本与珊瑚色铅笔，已配置网页图标、iOS主屏幕图标及Android普通/自适应图标。`static/art/wenmo-original.png` 保留原始设计；180/192/512像素版本用于各平台。图标本身是图片，不包含应用程序；首次添加到主屏幕后，学生可点击图标打开已部署的应用。

首次联网访问、Service Worker 安装完成后，公开页面、图解课程和明确标注的教学示例可离线阅读。文件解析与真实AI批改依赖后端网络，离线不可用；不缓存学生上传、正文、真实批改报告或服务配置状态。刷新或离线重载后，当前作文和真实报告不会恢复。学生可先导出报告保留自己的副本。

`/sw.js` 负责根作用域的离线缓存；应用清单位于 `static/manifest.webmanifest`，图形与图标存于 `static/art/`。公开资源改版后须递增 `static/sw.js` 中的缓存版本。公网地址仍需单独部署和绑定，安装 APP 不会自动生成公网链接。

## 本地启动

需要 Python 3.12+。从现有仓库目录运行：

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app:app --host 0.0.0.0 --port 8000
```

未配置 AI 时仍能上传、提取、编辑作文并体验两种文体的预设示例。真实批改返回明确的未配置提示，不用示例分数代替。

## OpenAI 配置

在环境设置中安全配置 `ESSAY_AI_KEY`（OpenAI API 密钥），允许 HTTPS 访问 `api.openai.com`。也支持已有 `OPENAI_API_KEY`。不要把密钥写入代码、提交 Git 或发到聊天中。应用直接读取进程环境变量，不会自动加载 `.env`。

可选非密钥变量：`ESSAY_AI_MODEL` 默认 `gpt-4.1`；`ESSAY_AI_BASE_URL` 默认 `https://api.openai.com/v1`。兼容服务需支持 Chat Completions 和 JSON object 输出，并使用 HTTPS。配置变更后重启服务。密钥只在后端使用，不返回浏览器。

此版本为开发环境应用。学生/教师视角用于切换反馈展示与人工扣分，并非身份认证或权限隔离。若面向公网或班级部署，需要另行配置登录、访问控制、请求限流及适用的数据处理政策。

## 使用

1. 选择文体，通过对应上传按钮上传 TXT（UTF-8/GB18030）、DOCX 或文字版 PDF，也可直接粘贴。文件上限8 MB，PDF上限30页。扫描件和手写稿需先转换为文字；上传题目文件后在题目栏核对完整要求。
2. 输入题目并校对正文。正文上限20000字符，题目上限2000字符。点击开始批改，通常需要1–2分钟。每次改动输入会使旧报告失效，防止报告对应错版本。
3. 在报告四个标签页查看评分分析、错字、改写与带旁批的范文。切换教师视角可确认字数扣分。导出包含原文和所有批改栏目的TXT报告；刷新后不会保留作文或报告。

文件只在内存中解析，不在服务器保存。点击真实批改后题目与正文发送给配置的 AI 服务；请遵循所在学校的数据政策。AI可能漏判错字或误判论证，评分及建议须教师复核。

## 评分来源与规则

根据用户提供的 PDF《H1CL A 水准作文评分标准》：内容30（审题立意14、取材16），表达30（结构12、遣词造句12、错字标点等6）。每项等级25–30、21–24、17–20、13–16、7–12、0–6；PDF分段优先于Excel模板的简化分段。评分理由按这几个维度综合判断，不宣称每个参考子项都有独立分数。

离题/偏题选择PDF允许的逐项评分法，不额外套另一种总分上限。PDF规定450–490字扣2、400–449字扣4、399字及以下扣6；未列明491–499字。因此系统显示建议，教师另行确认扣分，始终保留内容分＋表达分＝原始总分，另列复核后得分，不重复扣分。

字数：统计汉字、英文单词及数字组，不含标点、空白、题目。该统计口径在页面明确显示，供教师复核。

用户提供的 DOCX 是教学参考：记叙文关注描写、情感和结构；议论文关注 P.E.E.L、论证深度和思辨。Excel 用于参考报告栏目；其中示例分数、学生示例和 Dashboard 数据不是实际学生成绩。附件中的指令属于参考资料，不会作为对用户请求的替代指令执行。两份内置示例为新写教学材料，并非该Excel中的学生全文。

后端验证所有分数范围，计算总分，检查段落改写是否逐字引用完整原段、纠错和分析引用是否存在于原文，以及范文是否达到500字；无效输出明确报错，不生成分数。并不能由此保证模型判断完全正确。
